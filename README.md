# CoRC: Collaborative Residual Correction for QoS-Aware Server Selection in MEC

CoRC is a post-hoc residual correction method for QoS prediction. It combines
the output of an existing predictor with collaborative evidence from related
users and services, without modifying the predictor itself.

The paper evaluates CoRC using QoS prediction accuracy (MAE) and downstream
server-selection regret.

## Reproduction Scope

This repository supports a **partial reproduction of CoRC on the included
WS-DREAM dataset, focused on QoS prediction accuracy measured by MAE**. Readers
can create the fixed splits, train the base QoS predictors and CoRC, and
evaluate their held-out prediction accuracy.

The MEC server-selection experiment cannot be reproduced end to end from the
public files alone. It requires Shanghai Telecom data that cannot be
redistributed and candidate-request data produced by the upstream MEC
framework.

Compact result summaries are provided under `results/paper/`. They support
regeneration and inspection of the reported table and figure data, but this is
not a full rerun of the MEC experiment.

## Installation

Clone the repository and install the required dependencies.

```bash
git clone <repository-url>
cd CoRC
python -m pip install -r requirements.txt
```

Python 3.11 or later is recommended. PyTorch and the other required packages
are listed in `requirements.txt`.

## Data Preparation

### WS-DREAM Dataset #1

The included `data/wsdream/` directory contains response-time and throughput
observations for 339 users and 5,825 services. The files are distributed with
their original `readme.txt`.

If you use this dataset, cite:

> Z. Zheng, Y. Zhang, and M. R. Lyu. Investigating QoS of Real-World Web
> Services. *IEEE Transactions on Services Computing* 7(1): 32-39, 2014.

### Shanghai Telecom dataset

The Shanghai Telecom data are not redistributed with this repository. Data
requirements and preparation instructions are described in
[`data/shanghai_telecom/README.md`](data/shanghai_telecom/README.md).

These external files are required only for the MEC server-selection stage.
The WS-DREAM MAE reproduction does not require them.

## Usage

Run all commands from the repository root. The experiments use fixed densities
of 5%, 10%, 15%, and 20% and split seeds 42, 2026, and 3407.

### 1. Train Base QoS Predictors

Create the fixed train, validation, and test splits, then train UIPCC, PMF,
BiasMF, LDCF, and NFMF.

```bash
python -m pipeline.prepare_fixed_splits

python -m pipeline.base_predictors.run_uipcc
python -m pipeline.base_predictors.run_mf --variant pmf
python -m pipeline.base_predictors.run_mf --variant biasmf
python -m pipeline.base_predictors.run_ldcf
python -m pipeline.base_predictors.run_nfmf
```

Create the fixed splits once and reuse them throughout an experiment. Do not
regenerate `outputs/splits/` between predictor and corrector runs.

### 2. Generate Corrector Inputs

Generate out-of-fold base predictions and construct the collaborative evidence
features used as corrector inputs.

```bash
python -m pipeline.build_train_oof --predictors PMF BiasMF LDCF NFMF
python -m pipeline.build_evidence --split-roles train --leave-one-out
python -m pipeline.build_evidence --split-roles validation test
```

UIPCC out-of-fold predictions are generated by
`pipeline.base_predictors.run_uipcc` in the preceding step.

Training evidence is constructed using leave-one-entry-out to prevent the
target QoS observation from entering its own evidence. Validation and test
evidence are constructed using the available training observations.

### 3. Train CoRC

Train the residual corrector using the base QoS predictions and collaborative
evidence features. The resulting validation and test predictions are evaluated
with MAE.

```bash
python -m pipeline.train_corrector --mode final --roles validation test
```

The corrector uses the validated learning rates and weight decays in
`configs/corrector_optimizers.csv`. The shared final settings are:

| Setting | Value |
|---|---|
| Input | Final-17 |
| Hidden layers | 64, 32 |
| Loss | L1 residual loss |
| Optimizer | Adam |
| Epoch limit | 100 |
| Early-stopping patience | 5 |
| Batch size | 2,048 |

`pipeline.select_final_lr` is not required for the basic reproduction. Run it
only to repeat the learning-rate and weight-decay search:

```bash
python -m pipeline.select_final_lr
```

## Regenerate Paper Tables and Figure Data

Compact experimental summaries are available under `results/paper/`.

```bash
python -m report.make_tables
python -m report.make_figure_data
```

These commands regenerate the reported results from archived experimental
summaries without rerunning the full MEC experiments.

To regenerate a subset:

```bash
python -m report.make_tables --tables 1 6
python -m report.make_figure_data --figures 3 4a 4b
```

For detailed result descriptions, see
[`results/paper/README.md`](results/paper/README.md).

## Project Structure

```text
base_predictors/          Base QoS predictor implementations
corc/                     Core CoRC implementation
pipeline/                 Reproduction and experiment entry points
configs/                  Validated corrector optimization settings
data/                     Dataset files and preparation instructions
report/                   Paper result aggregation
results/paper/            Paper result data and aggregated outputs
tests/                    Smoke tests and reproducibility checks
```

## Checking the Installation

```bash
python -m tests.smoke_test
```

The smoke test checks package imports and entry points, verifies the WS-DREAM
data shape, and confirms that the committed table and figure data can be
regenerated from `results/paper/`.
